# 输出模板

先定档，再写。不要为了「节不是空的」而补齐精简档或大纲不需要的章节。标题用用户的语言。

本节是**档位定义的唯一出处**：每档写哪些节、节奏要求都在这里。SKILL.md 只管「什么需求 → 什么档」的映射。

负荷、车程、抵达离开、预算不可行见 [planning.md](planning.md)；发出前按其中的「发出前可行性校验」过一遍。

价格、开放时间、「必须预订」：用紧凑的 `（查询日期 YYYY-MM-DD，来源：…）`，或文首一行「资料截止」+ 文末出处表。规划建议不必每句都挂来源。查不到的事实按 [research-playbook.md](research-playbook.md) 的「数据查不到时怎么写」降级。

## 档次

**大纲**（「先给个大纲」）：只写第 1 节速览 + 每日一行标题。纯结构无需检索票价；若点名实际景点、路线或预订事项，核实会影响该建议的事实。

**精简**（周末 / 1–2 天 / 只要其中一块）：只写用得到的节。周末默认：速览 + 必订 + 逐日 + 精简打包；天气影响安排且有日期时再加天气。只要吃 / 住 / 打包且不写行程：只写那一节，仍核实具名推荐。只要交通：写怎么走 + 已核实价格或官方查询入口。不要为了凑节去补齐完整档。

**完整**（3–5 天、一城）：按下面 1–12 节选用相关内容。天气按 [live-data.md](live-data.md) 的适用条件加入；用不到的节可删。

**多城市 / 7 天以上**：默认速览 + 主线 + 每城重点 + 住/吃表；用户明确要详细逐日时展开每天的交通与时段。

**HTML**：对话里给摘要 + 一个 HTML 文件；未指定样式时默认杂志版（页头封面 + 主线 + 日卡 + 住宿卡），用户要求极简或打印优先时按其选择。结构、视觉和交互见 [html-guide.md](html-guide.md)，本文档只负责内容本身。

## 1. 行程速览

- 目的地、天数、出行月份/具体日期、星期
- 人数与同行类型
- 交通方式（自驾 / 高铁 / 飞机 / 混合）
- 节奏与主题
- 预算带：经济 / 舒适 / 豪华，人均或总预算区间
- 一句话：这次适合谁、不适合谁
- 季节风险：台风、酷暑、冰雪、旺季人潮 — 只写真正相关的；需要天气时按下节单独呈现
- 自驾再加：全程里程量级、过夜城市、过路费窗口（哪几天免费 / 哪几天要交）
- 有数字上限时：推荐合计 vs 上限；不够则按 planning 写清不可行

## 2. 天气（独立节）

仅当目的地、日期明确且天气影响行程时单独成节；酒店、餐厅、打包等单项回答无需天气。需写天气时不要只埋在「季节风险」里。

- 出行日在预报窗口内：只写对应日期的气温、天气与预警，带来源和查询日期；数据缺日时标出缺口
- 更远：只有来源可靠的历史气候才能给数字，并标「非预报」；近期参考不能冒充出行日气温
- 仍无可信数字时给官方查询入口及出发前复核时间，不编气温卡片
- 查法见 [live-data.md](live-data.md)。HTML 用 `#weather`

对话里也要单独写一节，不要埋进速览的一句话。

## 3. 出发前必订

清单。每行标明：建议提前 / 可到当地 / 可选。

常见行：

- 大交通（机票 / 高铁 / 自驾检查：ETC、备胎、台风）
- 住宿（每城 1 个主选 + 1 个备选，带片区和车位）
- 必须预约的票（博物馆、热门餐厅、轮渡、缆车、演出）
- 交通卡 / eSIM / 签证或过境签（只写需要核实的点）
- 保险、景区实名预约 — 这次用得到才写

用户已定酒店时，必订里写那一家，不要再塞 3 个新主选。

行程含热门预约（博物馆分时票、乐园、轮渡、网红餐厅）时，加一条 **出发前时间线**，把「什么时候订」写死：

```
T-30：大交通 + 住宿（旺季先订可取消的）
T-7：分时票 / 轮渡 / 演出 + 需要预约的餐厅
T-3：核天气与预警；动态事件则重算当天
T-1：值机 / 选座、门票二维码截图存离线、确认末班车船时刻
```

各渠道开售时间不同（有的提前 7 天、有的提前 30 天放票），写清**按哪条渠道、提前几天**，不要笼统写「尽早订」。

交付 HTML 时做成复选框（`<label class="check"><input type="checkbox" data-k="…">`），勾选状态由壳子的 `localStorage` 记住，写法见 [html-guide.md](html-guide.md)。

## 4. 怎么住

按城市 / 过夜点做短表：

| 选项 | 片区 | 为何选 | 参考价/晚 | 停车 | 预订 |
|---|---|---|---|---|---|
| 主选 真店名 | | | 区间 | 有/无/需确认 | 链接 |
| 备选 真店名 | | | | | |

默认 2 家。用户要比或档差大时最多 3 家。不要列 8 家。写明「周末/节假日会跳价，以下单页为准」。

先选片区，再选品牌。说明为什么这里比更便宜但很远的酒店值得（夜里好回、早餐、能走路、有车位）。

## 5. 怎么走

- 机场/车站 → 酒店，或自驾路线（高速名、过桥、易堵点）、耗时、费用量级
- 市内：步行 / 地铁 / 公交 / 出租 / 租车
- 多城市：城际怎么接、当天还能不能玩、行李是否先存
- 自驾：窄巷、景区车位、岛上能否开车、疲劳驾驶（规则见 planning.md）
- 自驾停靠：服务区节奏；用户说了能源再写加油/充电；用户说了车高再写限高
- 错站提醒：北京西 vs 北京南，东京成田 vs 羽田
- 飞机 / 高铁 / 火车：不要地图界面，列出参考价（高铁以 12306 为准，机票以航司官网为准）。一城地铁用官网票价表，不要调高德公交。见 [live-data.md](live-data.md)
- HTML：自驾段才画路线；飞机 / 高铁 / 火车段给价格表 + 搜索链接，不把这些段画成驾车。混合行程同时需要时保留路线图和城际票价表，见 [maps.md](maps.md)。

## 6. 逐日行程

```markdown
### D1 · 9 月 27 日（周日）· 主题

- **上午：** 地点 — 做什么、停留多久、票/预约、怎么去（步行 X 分钟 / 开车 X 分钟）
- **中午：** 店名 — 吃什么、人均带
- **下午：** 同片区下一锚点
- **傍晚/晚上：** 日落 / 夜景 / 轻松晚餐（店名）
- **备选：** 下雨或闭馆
- **当天路线（自驾）：** 出发 → 高速 → 到达；公里/小时；1 个停靠；导航链接
```

**日期写法（硬规则）**：逐日卡片和「每日行程总表」都要让用户一眼看到**几月几日**，不能只写 `D1` / `D2` 或 `9/27` 这种短码。

- 日卡标题行：`D1` 徽章 + **粗体日期** + 星期胶囊，三段分开排版，例如 `D1 ｜ 9 月 27 日 ｜ 周日`。日期和星期**不要挤在一格**。
- 「每日行程总表」：**日期与星期拆成两列**（`<td>9 月 27 日</td><td>周日</td>`），不要写成 `D1 · 9/27 周日` 这种混合单元格。
- 参考其他日期时补全，例如「D1（9/27）」「滕王阁（9/28）」「省博 10/1 预约」；只有文案真放不下时才用 `9/27` 短码，且同一份里首次出现必须是全写。
- 跨月要写月份（`9 月 30 日` → `10 月 1 日`），不要只递增日号。
- 特殊日标出来（假期首日、周一闭馆日、出发日 / 返程日），写进日期行或主题行，例如主题写成「国庆首日」。
- 打印时日期与星期保持黑字可读，不要只在彩色胶囊里显示。

- 锚点数量跟负荷走，不是必须填满 2–4
- 每个深核主锚点：建议停留、是否排队、是否早到、免费还是收费
- 抵达日和离开日按实际出发时间压缩
- 只有当季真能对上（日照、最晚入园、末班轮渡）才写钟点
- 有硬时刻（末班车 / 船、最晚入园）的日子，写出「最晚几点必须开始这一项」
- 写完当天过一遍 [planning.md](planning.md) 的「发出前可行性校验」，超时就砍锚点

## 7. 景区与票价

计划里进入深核的核心 / 收费 / 必订景点，或容易排队的点：

| 景区 | 开放/闭馆 | 票价 | 建议停留 | 预约 | 停车 | 备注 |
|---|---|---|---|---|---|---|

价格没查到：保留这一行，写「下单页确认」+ 官网或预订链接。

完整档不等于每个点都深核：**完整输出 ≠ 完整研究**。非核心景点只写名称、建议停留和官方入口，不占这张深核表。深核对象的数量上限以 [research-playbook.md](research-playbook.md) 的「候选上限」为唯一出处。

## 8. 吃什么

按片区或按餐，不要做 20 条必吃榜。

| 店名 | 片区 | 点什么 | 人均 | 排队/预约 | 链接 |
|---|---|---|---|---|---|

候选数量上限以 [research-playbook.md](research-playbook.md) 的「候选上限」为唯一出处；不要为了填满表格主动扩展候选池。尊重已说的饮食。没说也留一家清淡 / 素食备选（可与备选同一家）。点出常见坑（先吃后称、称前不报价、景区门口托）。

## 9. 预算

写区间，不要假精确。标明币种、人均还是总计、不含什么。

| 项目 | 经济 | 舒适 |
|---|---|---|
| 大交通或油费过路 | | |
| 住宿 | | |
| 餐饮 | | |
| 门票 | | |
| 市内交通/停车 | | |

写明购物、酒水、保险、签证是否排除。

用户给了硬上限：同一节展示 **推荐合计 vs 上限**。点明哪些升级会把推荐合计顶破上限。不够则按 planning.md 处理。

## 10. 打包与当地注意

只写这个气候和这种交通需要的。安全、支付、插头、常见骗术。出境补紧急电话。寺庙/清真寺着装有要求时写一句。

## 11. 可砍可加

3–5 条：累了就砍，有余力或多半天就加。

## 12. 出处

条目：网站或搜索词、支撑了什么、查询日期。用户要了具体酒店/饭店/门票时必给。
