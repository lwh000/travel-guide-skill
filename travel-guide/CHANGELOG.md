## 2.10.0 — 2026-09-16

把「降生成攻略的搜索次数 / Token / 时长」落到硬规则上：不再只靠总预算，而是加轮次、搜索、打开的硬上限和统一的硬停止条件。不改 HTML / validator / security 的行为契约，只收紧研究执行层，并把重复规则收拢到单一出处。

- **Fast 改「轮次硬上限」**：第 1 轮 ≤2 次批量搜索、第 2 轮 ≤1 次补查，**第 2 轮结束禁止搜索**，不允许自行开第 3 轮；Fast 搜索 ≤3 次、打开 ≤4 个、图片 ≤1 次。Standard / Deep 也按表收口（Standard ≤4 轮 / 搜索 ≤6 / 打开 ≤7；Deep ≤6 轮 / 搜索 ≤10 / 打开 ≤12）。
- **Fast 预算下调**：Fast 8–10、Standard 18–20、Deep 30–35 单位（旧值 15 / 30 / 50）。**预算耗尽立即停止研究并进入写作**，不因「还有一个事实没确认」突破。
- **统一硬停止条件**（6 条，命中任一即停）：达到轮次 / 搜索 / 打开上限、剩余预算 ≤20%、信息已够定结构、后续搜索只增细节不改结构。第 6 条专门挡住「再确认一下营业时间 / 景点 / 酒店」的无限细化。
- **完整输出 ≠ 完整研究**：完整档只表示最终输出完整，不代表要逐个深核餐厅 / 景点 / 酒店 / 交通节点；只核实最终会写进攻略的关键实体，不为了凑完整度增加候选。
- **候选上限**：住每城 1 主 + 1 备、吃每餐 1 主 + 1 备、景只查最终进入行程的点、交通只核影响结构的段。没有要求大量候选时不得主动扩展候选池；已有可用选项时不得重复搜同类。
- **来源要求 ≠ 交叉验证要求**：S/A 来源已满足事实核实要求时，不得为「再加一个来源」重搜；同一事实只核一次，只有来源冲突才重新核验。
- **信息充分阈值 + 防链式扩张**：核心目的地 / 景点 / 住宿区域 / 主要交通 / 必订信息 / 关键预订入口齐了就停；新发现的地点默认不自动加入研究范围。
- **定向打开网页**：搜索摘要已足够时不打开页面；只有官方硬事实、具体营业时间 / 票价 / 预约规则、摘要不足时才开。
- **天气、图片解耦**：天气独立执行、失败不触发重复研究、不影响结构时不为天气再搜；图片搜索是一次性动作，不得因找不到理想图反复搜。
- **SKILL.md 精简**：从约 19.5KB 压到约 10.7KB（-45%），只留总体工作流 / 模式选择 / 硬预算 / 硬停止条件 / 输出要求 / 文件加载规则；详细研究规则统一放 `research-playbook.md`，收集问卷 / 缺省值 / 锁定项 / 改需求范围 / 减负顺序移到 `planning.md`，其他文件只引用。
- **消除重复规则**：预算、轮次、搜索 / 打开上限、候选数量、天气、图片、HTML 不重搜等只在 `research-playbook.md`（天气在 `live-data.md`）定义一次，其他文件改为引用。
- **发布包清理**：`release.py` 打包与完整性清单一律排除 `__pycache__/`、`*.pyc` / `*.pyo`、`local-keys.json`、开发日志（`logs/`、`*.log`）和临时测试文件（`_*.py`、`*.tmp` / `*.bak` / `*.orig`）。**正式 ZIP 只通过 `release.py --zip` 生成，禁止直接压整个工作目录。**
- **validator 保持纯校验**：`validate_html.py` 只做输出结构 / 格式 / 完整性检查，明确不搜网页、不补研究、不重新验证旅游事实、不触发外部工具。
- `eval.md` 新增案例 56–65（第 3 轮硬停、预算未用满也停、同事实不重核、候选不扩张、防链式扩张、天气 / 图片解耦、validator 不重搜、定向打开）。

## 2.9.1 — 2026-09-15

只改研究预算执行层，不碰已经稳定的 HTML / validator / security 体系。普通攻略的预算不再和「完整档」的深核要求互相拉扯，目标是减少为了满足规则而产生的额外检索轮次。

- **完整档不再等于每个点都深核**：只深核核心 / 收费 / 必订景点；非核心景点给名称、建议停留和官方入口。Fast 每天最多 1 个核心锚点 + 1 个顺路补充点进入深核。
- **第一轮批量检索**：Fast 第一轮只发 1–2 次搜索调用，每次尽量合并多个 query，一次覆盖核心景点、住宿候选、餐饮候选、必订和大交通；不得逐酒店 / 逐景点 / 逐餐厅串行开轮次。
- **预算按独立动作计费**：同一次批量搜索里的多个 query 合计 1 次搜索；内部维护 `{档位} used/limit`，不展示给用户。
- **剩余预算降级**：剩余 ≤20% 后禁止新增酒店 / 餐厅 / 景点候选，也不能开始交叉验证或图片搜索；剩余只用于会改变行程结构且不补就无法交付的硬事实，0 时彻底停止。
- **图片不阻塞正文**：要 HTML 仍按杂志版排版，但只有核心事实完成后且尚未进入降级区时（Fast >3 / Standard >6 / Deep >10 单位）才做一次 Commons 批量搜索；已进入降级区直接使用 `.art-fig`。
- **validator FAIL 不重开研究**：先修结构、删无效字段或降级展示；只有自驾地图缺会挡住已确认路线的关键坐标时，才允许最多补 3 单位。
- `live_data.py` 单次网络请求超时由 12 秒缩到 8 秒，减少天气源失败时的真实等待。
- `eval.md` 新增案例 50–55（完整档深核边界、批量检索、剩余预算降级、内部计数器、validator 不重搜、低预算图片降级）。
